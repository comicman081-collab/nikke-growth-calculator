# V34.7.10 — BlaBla 186명 보유 로스터 전파 및 5덱 복구

## 실제 원인

V34.7.9에는 서로 다른 두 문제가 겹쳐 있었다.

1. 오래된 표준 로스터 래퍼가 고정된 내장 캐릭터 목록만 보고 `getOwned()`를 다시 만들었다. BlaBla 동기화는 186명을 중앙 문서와 동적 카탈로그에 저장했지만, 이후 79명의 보충 등록 캐릭터가 전역 `getOwned()`에서 빠져 자동편성에는 107명만 전달될 수 있었다.
2. 저메모리 5덱 후보 제한이 5개의 서로 겹치지 않는 팀을 만들지 못했을 때, 실제 보유·역할 수를 보여 주지 않고 `insufficientRoster / team count 0 / slot count 0 / duplicate members`라는 잘못된 통합 오류를 렌더링했다.

## 수정

- 동적 `catalog()`와 중앙 저장 문서를 합쳐 `getOwned()`와 로스터 수를 계산한다.
- 계산 모델이 없는 보충 캐릭터도 내 로스터에는 그대로 186명 보존한다.
- 계산 모델이 없는 캐릭터에는 가짜 스킬 계수나 점수를 부여하지 않고, 정밀·시뮬레이션·5덱 계산 후보에서만 제외한다.
- 실제 동기화 큐브 중복 배치를 보존한다.
- 기본 제한형 탐색이 4팀에서 끝나면 남은 보유 계산 프로필로 5번째 팀을 보완한다.
- 5팀·25명·정체성 중복 0을 통과한 결과만 렌더링한다.
- 진짜 역할 부족일 때만 계산 가능 고유 수, B1, B2, 활성 B3, FLEX 수를 구체적으로 표시한다.
- 성공 결과를 로스터 지문으로 캐시하고, 동기화 업데이트 시 캐시를 즉시 비운다.
