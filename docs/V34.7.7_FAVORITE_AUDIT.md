# V34.7.7 ENIKK 애장품 단계 감사

## 결론

V34.7.7은 숫자를 추측하지 않고 ENIKK 배포 데이터와 앱의 실제 소비 코드를 기준으로 애장품 상태를 해석한다.

- ENIKK 애장품 마스터 TID: 라플라스 `200401`, 슈가 `200501`, 폴리 `201001`
- ENIKK 로스터 단계: 유효한 SSR 애장품 TID가 없으면 Phase 0, 있으면 `favoriteItemLv` 0/1/2를 앱 Phase 1/2/3으로 변환한다.
- 스킬 레벨: `skill1Lv`, `skill2Lv`, `ultiSkillLv`는 단계와 독립적으로 `skills.skill1`, `skills.skill2`, `skills.burst`에 그대로 유지한다.
- 단계별 변형 슬롯:
  - 폴리: Phase 1 스킬 1 → Phase 2 버스트 → Phase 3 스킬 2
  - 슈가: Phase 1 스킬 1 → Phase 2 스킬 2 → Phase 3 버스트
  - 라플라스: Phase 1 스킬 2 → Phase 2 버스트 → Phase 3 스킬 1

## ENIKK 배포 감사 증적

2026-08-26 감사에서 ENIKK Next.js 런타임이 참조한 49개 청크를 전부 수집했고, 14개 관련 청크에서 TID·단계·스킬 레벨 필드를 교차 확인했다. 청크 수집 실패는 0건이었다.

- 애장품 마스터 청크: `1741.3e09fc33232d9a00.js`
- 해당 청크 SHA-256: `152e22b9a126b0ebdf6eef218929d3a9ccd26fea77382b0cdb00cd6df7a047e7`
- 로스터 필드가 함께 확인된 배포 청크: `1427-d56f8db3e4fe881a.js`, `3923.9c30749572fcd979.js`, `4710-13a8e4013df1da7d.js`
- 확인 필드: `favoriteItemTid`, `favoriteItemLv`, `skill1Lv`, `skill2Lv`, `ultiSkillLv`

## 수정 사항

1. 일반 캐릭터 저장값을 애장품 ID로 이관할 때 `favoriteItemPhase`를 무조건 3으로 올리던 `Math.max(..., 3)` 경로를 제거했다.
2. 이관 시 4 미만의 실제 스킬 레벨을 강제로 4로 올리던 경로를 제거하고, 소유 중인 원본 행의 1~10 레벨을 그대로 보존한다.
3. 계산 컨텍스트와 공통 성장 컨텍스트에 `favoriteItemPhase`를 전달한다.
4. `NIKKE_V3477_FAVORITE_PHASE_API`가 TID·Phase·활성 변형 슬롯·원본 스킬 레벨·계산 서명을 한 번에 결정한다.
5. 폴리·슈가·라플라스 계산은 Phase 0에서 일반 스킬, 각 Phase에서 해당 슬롯만 애장품 변형을 사용한다.
