# V34.7.8 BlaBla 4화면 연산 동기화

## 목적

BlaBla 공개 로스터에서 가져온 한 개의 중앙 로스터 문서가 **정밀**, **내 로스터**, **시뮬레이션**, **5덱 자동 구성**에서 서로 다른 값으로 갈라지지 않고 동일한 성장·장비·애장품 정보를 사용하도록 검증하고 고친다.

## 발견한 실제 결함

V34.7.7의 5덱 후보 생성기는 중앙 로스터에서 프로필을 만든 뒤 `installGrowthContext(rows)`에서 성장 컨텍스트를 다시 축약했다. 이 과정에서 다음 값이 누락됐다.

- `favoriteItemPhase`
- `equipmentAttack`
- `equipmentHp`
- `equipmentDefense`
- `equipmentObservedSlots`
- 전체 오버로드 합계
- 수동 보정과 실측 보정

따라서 BlaBla에서 애장품 Phase 3과 실측 장비를 정상적으로 가져와도 5덱 점수 계산 순간에는 Phase 0과 장비 미관측 상태로 되돌아갈 수 있었다.

## 수정

- 5덱 후보용 성장 컨텍스트가 중앙 로스터의 레벨·한계돌파·코어·스킬·애장품 단계·큐브·오버로드·실측 장비 ATK/HP/DEF/부위 수·수동/실측 보정을 전부 보존한다.
- 즉시 공유 컨텍스트도 같은 필드를 보존한다.
- 동기화 완료 메시지에 시뮬레이션을 명시한다.
- `NIKKEV3478BlaPropagation` 진단 API를 추가해 중앙 로스터, 정밀 프로필, 공유 계산 컨텍스트의 필드 동일성을 검사한다.

## 결정론적 브라우저 통합 검증

`tests/verify-blabla-propagation-browser-v3478.mjs`는 실제 앱의 동기화 함수와 UI/계산 엔진을 Chromium에서 실행한다.

1. 같은 출처의 BlaBla 브리지 응답을 실제 `NIKKEV3472BlaPublicSync.sync()`에 전달한다.
2. 내 로스터 편집기에 레벨, 돌파/코어, 스킬 2/7/9, 애장품 Phase 3, 큐브, 오버로드, 4부위 실측 장비가 표시되는지 확인한다.
3. 정밀 탭에 같은 값이 적용되고 실제 정밀 계산값이 생성되는지 확인한다.
4. 시뮬레이션의 정규화 프로필과 `damageBasis.gearAttack`이 중앙 로스터를 소비하는지, Phase 0/3 피해가 달라지는지 확인한다.
5. 5덱 자동 구성에서 후보가 생성되고 중복 없는 25명·5팀이 완성되는지 확인한다.
6. 5덱 점수 산정 중 슈가의 Phase 3, 스킬 2/7/9, 실측 장비 ATK/HP/DEF/4부위가 그대로 들어가는지 계측한다.

## Cloudflare 실배포 검증

`tests/verify-cloudflare-production-v3478.mjs`와 전용 GitHub Actions는 `main` 배포 후 다음을 실제 production URL에서 확인한다.

- HTML이 V34.7.8 및 4화면 전파 마커를 제공
- `/api/blabla/sync`가 V34.7.8이며 Global 게임 세션이 설정됨
- 공개 프로필 POST가 GLOBAL 84 서버의 캐릭터 요약·상세·상태 효과를 실제로 반환
- 결과 증적을 JSON 아티팩트로 보존
